# Code map: how the game works now

**Date:** 2026-11-09

How each part of the code works, where it lives, and the traps found so far. Read the part you are about to change, not the whole file. Moved here from `CLAUDE.md` so a new chat starts cheaper. Keep it current: when a part changes, change its line here.

## Game systems

- **Player** (`scripts/player/player.gd`, `scenes/player/player.tscn`): 8-way movement, 4 facing poses (`Player.Facing`, sticky: kept while within 60° of the walking direction), feet collision 20×10, `Reach` Area2D. Tools `Player.Tool` (HOE, WATERING_CAN, SEEDS, HAND, HOLY_WATER, BUILD, SWORD) on keys 1–7, Q/E pick a seed (`seed_index` into `Inventory.CROPS`), or a building with the Build tool (`building_index` into `Inventory.BUILDINGS`). Signals `tool_changed`, `tool_used(tool)`. F calls `interact(player)` on the first overlapping area that has that method
- **Animation**: idle sheet `assets/player/player_idle.png` (4 frames 48×64: down, up, left, right); walk sheets `walk_down/up/side.png` (4 frames, 8 fps, exported on Player; side faces left, right = `flip_h`). A direction without walk art falls back to idle + bob
- **Map**: 76×26 tiles; clean shore (rough ellipse in the west 40×26, must never move: saves store cells by position) surrounded by cursed ground that blocks walking; old farmlands to the east with 3 clean clearings, centers (50, 7), (58, 18), (69, 12), the last for the shrine. The outer ring must stay cursed, because nothing else stops the player leaving the map. `scenes/farm/ground.tscn` is generated by `tools/build_farm_map.gd` (also builds `data/tilesets/ground_tileset.tres`: sources 0 grass, 1 cursed with collision, 2 soil dry, 3 soil wet). Rerunning overwrites hand painting; the tileset is only built if missing, because saving it drops its UID
- **Ground textures** are 128×128 (4×4 tiles); each cell uses the piece at (x mod 4, y mod 4) via `Farm.texture_coords()`
- **Farm** (`scripts/farm/farm.gd`, node `Main/Farm` with Ground, Soil, WetEdges, SoilEdges, CurseEdges, Highlight, Healing): any clean grass can be tilled unless a solid object stands on the cell (`is_farmable()`, a physics shape query); target cell = tile in front of the feet (`target_cell_for()`), with aim assist in `smart_target_for()`: if the tool can't use that tile, the tiles beside it are tried, nearer side first, except for `EXACT_TOOLS` (Hoe, Build); `can_use(tool, cell)` drives the highlight (`Farm/Highlight`, `TileHighlight`: the `tile_cursor.png` corners as a 9-slice, 4 px outside the tile, white = usable, red = not, pulsing; stretched for holy water) and `_on_tool_used`. Tilled = a Soil layer cell; watered = SOIL_WET source. `crops: Dictionary[Vector2i, Crop]`, crop nodes go in the y-sorted `World`. Hand tool on a ripe crop calls `harvest(cell)`; the soil stays tilled so the cell can be replanted. The Hoe on empty soil calls `untill(cell)`; soil with no crop for `soil_idle_nights` (3) turns back to grass overnight (`_age_empty_soil()`, counts saved as `soil_idle` in `farm_state`), and facing empty soil warns on its last night only. `Farm/SoilEdges` draws ragged grass over soil beside grass (`assets/tiles/grass_edge.png`), and `Farm/WetEdges` a thinner ragged edge of watered soil over dry soil (`wet_edge.png`, half as deep so each watered tile stays readable); call `_refresh_soil_edges()` (refreshes both) after any soil change, watering included
- **Smart action (the classic Action button; Farm mode reuses its order)**: `Farm.smart_action(cell)` returns a `Farm.Action` (what the Action button would do) and changes nothing; `Farm.ACTION_TOOLS` gives the tool behind each one. `Farm.run_action()` does it, from the `action` input (R, or the big phone button) through `Player.action_pressed`; the selected tool stays selected, and `_use_tool(tool, cell)` does the work for tools and Action alike. `action_target_for()` is its aim assist: the tile ahead wins if it has any action, and tiles beside it are never tilled. For `action_object_pause` seconds after a farming tap it won't use objects, so fast tapping can't open a menu. Order: swing (has a sword, and `CreatureSpawner.nearest_within()` finds a creature within `action_swing_distance`; `Player.swing_at()` turns and swings straight at it), interact (`Player.use_nearby()`, which prefers an object's optional `action_interact()`), then `_tile_action()`. The door's `action_interact()` opens `HUD/SleepMenu` (`SleepMenu`, built in code, No focused first); F still sleeps at once. Menus with `close_action` `interact` also close on `action`. On phones the cursor and status text follow Action, unless Holy water or Build is selected (`USE_BUTTON_TOOLS`). `action_changed` tells `TouchControls.show_action()`, which shows the icon (`ACTION_ICONS`), dims the button on NONE, and shows "!" under menus `Player.action_target()` only takes objects inside a small circle in front of the player, and skips areas whose optional `can_interact()` says they'd do nothing (empty box, restored shrine); F uses `interact_target()` and still reaches anything in reach
- **Controls (storage controls, the only ones players get; `docs/28_...`)**: `GameState.carry_mode` is on unless a test passes `--classic-controls` (tests not named `test_storage_*` do, until the classic code is removed). `Inventory.bag` counts what's carried (totals stay the truth); `plant_set`, `combat_set` + `combat_slot_2/3` and `build_set` say what the big button may use. `Farm._carry_action()` farms, fights or builds by `Player.mode` (Farm, Combat, Build; key C or 1-3, or the mode button: tap for next, hold for the wheel in `TouchControls._input()`). Objects are tapped (`WardTap.tap_object()`). `StorageMenu` is the chest; `SetsMenu` is the bag with pages Bag and Modes (`show_page()`, `open_on()`). Any new way of gaining an item must call `Inventory._carry()`, and any new use must check `carried()`
- **Farm mode**: `Farm._farm_action()` does only the farm jobs that are on (`Inventory.farm_jobs`, `toggle_job()`), with what's carried. Holy water is only used on a cursed tile straight ahead
- **Combat mode**: three combat buttons beside the big button, each holding up to three weapons (`Inventory.combat_slot(i)`, `WEAPONS_PER_BUTTON`), a weapon on one button only. A tap picks a button, a tap on the picked one goes to its next weapon (`tap_combat()`, `combat_pick`, `combat_turn`, `_fix_combat_pick()`); dots show which (`TouchControls._show_dots()`); empty buttons are hidden. The big button fights with `Farm.weapon()` (empty for a bow with no arrows or a sling with no stones) and keeps one picture (`TouchControls.attack_icon()`); with nothing to do it shows its mode's picture, dimmed (`_idle_icon()`). Q/E pick a button on computers. Each morning starts on button 1 in Farm mode
- **Weapons**: the sword (every game starts with one, `give_starter_kit()`), the bow (`Bow`, `Arrow`, needs arrows), and six basic weapons from one table, `BasicWeapons.STATS` (club, pitchfork, sickle, torch, sling, throwing stones): melee ones reuse `Sword.swing(direction, weapon)` with their own picture, reach, arc and speed; the torch pushes harder and burns out after 20 swings (`Inventory.burn_torch()`); the sling and stones throw a pebble `Arrow` via `Player.throw_at()`, spending a carried stone (`use_stone()`). Recipes are `RecipeData.Result.BASIC_WEAPON` with a `weapon` id
- **Build mode**: one tool at a time, `Inventory.build_tool` (Place, Move, Pick up; the build tool button beside Action, key V). Move lifts a building, which stays in place faded in `Farm.lifted` until it's put down (`_lift()`, `drop_lifted()`, `lift_changed`); leaving the mode or changing tool puts it back. Pick up refuses with a full bag
- **Phone buttons**: Action (the big button), the mode button, Bag, Tasks, the old book, pause, and in Combat or Build mode the combat buttons or the build tool button. Menus are centered over them; the buttons are pausable, so they wait under a menu until it closes. The classic Heal, Seed and Build X buttons only exist for the older tests
- **Moving buildings (classic controls only)**: `Farm.mover` (`BuildingMover`, phones only) reads touches in `_unhandled_input`: hold a building for `HOLD_SECONDS`, drag, let go. `Builder.cell_at()` finds it by its art, `TouchControls.is_free_spot()` keeps the joystick and buttons first, and `Farm.move_building()` calls `Builder.move()`, which skips the bag. Letting go on red, a menu or the day changing cancels
- **Old book**: `BookMenu` opens from the Bag's Book button or key B (`book`). The pages are in `BookPages.PAGES` (percent healed, title, text, with {action} and {heal} filled in per device). `Progress.book_pages` is saved and only goes up, so pages stay if land is lost; `set_healed_percent()` sends the notice. The Bag's help line now shares the top row with Book and Build, on computers too
- **Crops**: `CropData` resources in `data/crops/` (radish 3 days, carrot 5, pumpkin 8, wardthorn 4; seed and sell prices set), listed in `Inventory.CROPS`. `Crop` (`scenes/farm/crop.tscn`): `days_grown`, `_stage_for()` (sprout after the first watered night; the last stage only when ripe), `is_ripe()`. Crops show a small icon when they need the player (`Crop.show_need()`, `Farm._refresh_crop_needs()`: a water drop only, in `assets/ui/need_water.png`; a ripe crop shows by its own look. `CropData.ripe_glow` adds a breathing light and motes, and `ripe_animation` swaps in looping frames). Facing a crop shows `Farm.crop_status()` on the HUD's CropStatusLabel, through the `target_status_changed` signal. Frames: radish 32×32, carrot 32×40, pumpkin 40×32 (kept at real pixel size; the sprite offsets by texture height)
- **Days**: house door (`scenes/farm/house.tscn`, Door Area2D) → `GameState.request_sleep()` → HUD fades out → `Progress.end_day()` emits `day_ended` (Farm grows watered crops, dries all soil) then `day_started`
- **Balance**: tunable numbers are in `data/balance.tres` (`GameBalance`), read through `GameState.BALANCE`
- **Cleansing**: `Farm/Healing` (`scripts/farm/healing.gd`) owns everything about healing; Farm calls it as `healing`. `Inventory.holy_water` is bought at the stall, and new games start with `start_holy_water` (2), so healing can happen on day 1. `Healing.cleanse(center)` heals the cursed cells in a 3×3 patch, costs one use, and costs nothing if there's nothing to heal; `is_cleansable()` protects the outer ring. The land heals at once; `scenes/farm/cleanse_effect.tscn` (`CleanseEffect.play()`) only draws the old tiles fading out from the center, with a light flash and sparkles, then frees itself. It sizes itself from the cells, so it also suits a large cleanse
- **Shrine**: `scenes/farm/shrine.tscn` (`Shrine`, an Area2D with a StaticBody2D child) at (2224, 412). F emits `activated`; `Healing._on_shrine_activated()` spends `shrine_cost` holy water, sets `restored` (swaps the sprite, turns on its light) and heals a circle of `shrine_radius` through `_cleanse_cells()`. Saved as `shrine` in `farm_state`
- **Curse edges**: `Farm/CurseEdges` (`scripts/farm/curse_edges.gd`, extends `TileEdges` like `SoilEdges` and `WetEdges`) draws ragged pieces from `assets/tiles/curse_edge.png` over clean tiles beside cursed ones, for looks only; collision still follows the tiles. `refresh(ground)` rebuilds them after any heal, and any new way of changing ground tiles must call it. Rerun `tools/build_curse_edges.gd` (builds the curse, grass and wet edge atlases, each with its own depth in `ATLASES`) then `--import` if `cursed_ground.png` or `grass.png` changes
- **Curse returning (kept after the 2026-11-09 play test)**: each morning from `curse_return_first_day` (and after loading), `Healing.mark_tonight(can_take)` picks `Healing.tiles_tonight()` healed tiles (`curse_return_per_night`, plus 1 for each `curse_growth_percent` healed) beside the curse into `marked` (seeded by the day, so not saved), drawn by `CurseMarks`. Call `refresh_marks()` after anything that could save a tile. At night, before lanterns heal, `curse_returns(can_take)` turns the ones still at risk back to cursed. Bare soil is lost with its tile, and `Farm._curse_comes_back()` blights a food crop instead of taking its tile (`Crop.blighted`: stops growing, Hand gives `blighted_crop_money` and a curse shard). This runs before the soil dries. `Farm._can_curse_take()` skips buildings, gatherable spots, ward plants and blighted crops, and anything inside the `guard_radius` square of a placed lantern, within `shrine_radius` of a restored shrine, or inside the square of a ward plant. 0 tiles turns it off
- **Guards and water**: a ward plant (`Farm.ward_reach()`: nothing around it as a seed, then `ward_dry_radius`, `ward_radius` while watered, `ward_ripe_radius` once ripe, with no water, because Action can only burst a ripe one) and a building with `guard_radius` protect a square, measured by `Farm.tiles_apart()` (a diagonal step counts as one). In play, light shows the area: `Crop.show_guard()` sizes a ward plant's glow to its reach. `TileHighlight.show_area()` only shows while placing a building with `guard_radius`. `BuildingData.min_spacing` keeps the same building apart (`Builder.has_room()`, `Farm.spacing_status()`; existing saves keep what they have). `Inventory.can_water` holds `can_capacity`, isn't saved, and is full each morning; `scenes/farm/well.tscn` has an `Interact` area (`well.gd`) that refills it. `World/StartingWell` is fixed like the house, because `starting_objects` would remove a new movable object from older saves, and `Farm._clear_under_starting_well()` clears what an old save grew there
- **Wardthorn**: a `CropData` with `ward_radius` and `burst_radius`. It's rare: `daily_stock` limits the stall (`Inventory.seeds_left_today()`), and `space_radius` claims the tiles around it (`Farm.in_ward_space()`, `_has_room_for()`). Nothing marks those tiles, and `ward_space_status()` explains them when faced: tint, roots and a ring were all tried and felt distracting. `sway` leans it gently. Buttons never burst a ripe one: phones tap the plant within 2 tiles (`WardTap`), computers use the Hand tool, and both raise `burst_asked`, so the HUD asks first. Then `Healing.burst()` runs instead of `add_harvest()`. It has no harvest row in the bag, only an item line for its seeds. It's the 4th crop in `Inventory.CROPS`, so the shop's holy water row is index 4
- **Finds and progress**: `data/buried_finds.tres` (`BuriedFindTable` of `BuriedFind`) places rewards (money, seeds, holy water) on cursed cells, each marked by `scenes/farm/find_glimmer.tscn`. Healing digs them up through `Inventory.give_find()`, which sends `notice` to the HUD's NoticeLabel. Dug-up finds leave `finds` and are saved as `dug_finds` in `farm_state`, because their land can return; older saves count any find on a healed cell as dug. `Progress.healed_percent` comes from `Healing._report_progress()`, shown on the HUD, and isn't saved either
- **Selling**: `scenes/farm/shipping_box.tscn` at (848, 368): F calls `Inventory.ship_all()` (all of `harvest` into `shipped`); `end_day()` pays `shipped_value()` before `day_ended`
- **Shop**: `scenes/farm/shop_stall.tscn` at (352, 352): F calls `GameState.request_shop()` → `scenes/ui/shop_menu.tscn` (under HUD; pauses the tree, `process_mode` Always, seed rows built from `Inventory.CROPS`, then holy water) → `Inventory.buy_seed(crop)` / `buy_holy_water()`. The stall sells `holy_water_daily_limit` a day (`holy_water_sold_today`, not saved, because saves happen in the morning)
- **Save/load**: `SaveGame` (`scripts/autoload/save_game.gd`) owns the file. `Progress.end_day()` calls `SaveGame.save_game()` last; its `_ready()` calls `load_game()`, so the game always resumes in the morning and anything done after the last sleep is lost. File: `user://save.cfg` (ConfigFile, `SAVE_VERSION`; missing, unreadable or other-version files start a new game), written through `save.tmp` and a rename so a crash can't damage it. `tests/fixtures/save_v1.cfg` is a real older save that must keep loading: never regenerate it to pass a test. Farm writes `SaveGame.farm_state` (cleansed cells, tilled cells, crops) at the end of `_on_day_ended` and rebuilds from it in `_ready`. Not saved: partly hit trees and rocks, player position, watered soil (dry at save time), `shipped` (paid before saving). New Game on the title screen starts over
- **Lighting**: `Main/Mood` CanvasModulate darkens the world (HUD isn't affected, it's a CanvasLayer). `scenes/farm/lantern_post.tscn`: origin at the post's base, `Light` PointLight2D at the lamp (24, -32), radial `GradientTexture2D`, 128px radius. 4 posts in `World` (door, stall, farm south corners). `lantern_light.gd` makes the light flicker
- **Autoloads**, in load order (`SaveGame` must come after the two it loads into). `GameState` (`game_state.gd`): only what the whole game shares: `BALANCE`, `notice`, `touch_mode`, `controls()` and the `request_*()` calls with their signals. `Inventory` (`inventory.gd`): what the player owns (`money`, `seeds` (start: radish 10, carrot 5, pumpkin 3), `harvest`, `shipped`, `materials`, `buildings`, holy water, upgrades), the lists (`CROPS`, `MATERIALS`, `RECIPES`, `BUILDINGS`), buying, crafting, shipping, and `inventory_changed`. `Progress` (`progress.gd`): `day`, `end_day()`, the guide, `hearts`, `healed_percent`, `day_changing`, and `day_ended`, `day_started`, `hearts_changed`, `fainted`. `SaveGame` (`save_game.gd`): the file, `farm_state`, `start_new_game()`, `discard_unsaved()`
- **Gathering**: `Farm/Gathering` (`scripts/farm/gathering.gd`) places `Gatherable` objects (`scenes/farm/gatherable.tscn`) in `World` from `data/gather/spots.tres`; kinds are `GatherData` in `data/gather/`. Hand tool on one: 3 hits, then material and remains (a stump is solid, rubble isn't). Ones on cursed land stay hidden until `Healing.land_healed`. They fade while the player is behind them. Gathered ones grow back after `regrow_days` nights (`Gathering.advance_day()`), waiting if the cell is tilled; saved as `gathered` in `farm_state`
- **Buildings**: `BuildingData` in `data/buildings/`, listed in `Inventory.BUILDINGS`; crafted ones not yet placed are counted in `Inventory.buildings` (saved). `Farm.can_build()` needs clean grass with nothing on it, and its query also sees interact areas and the player. `Farm/BuildPreview` shows the selected building on the target tile, green or red. `Farm/Builder` places them in `World` and saves them as `buildings` in `farm_state` (cell and id). The Hand tool picks placed ones back up. The map's own shipping box, workbench and 4 lantern posts are adopted by `Builder.adopt_starting()` at startup (BuildingData with `starting_only`, which the Build tool skips while none are in the bag; map lanterns are `old_lantern_post`, no healing), so they move the same way; saved as `starting_objects` (names still in place; missing = all stay). House and shop stall are fixed (`docs/17_...`). `Inventory.BUILDINGS` is a `var` filled with `load()`, because preloading the box from Inventory is a load loop. A placed building with `heal_radius` above 0 (lantern: 4) heals the nearest cursed tile each night through `Healing.heal_nearest()`. One with `water_radius` above 0 (well: 2, a 5×5 area) waters tilled soil each morning and after loading, in `Farm._water_from_buildings()`
- **Sword**: crafted once (`Inventory.has_sword`, saved; with storage controls every game starts with one). **Bow** (storage controls): `Inventory.has_bow`, `arrows`, `Player.bow` (`Bow`, added in code), `Arrow` flies in `World`; `Farm.weapon()` is the picked combat button's weapon (`Inventory.combat_pick`; three buttons of up to three weapons, a tap on the picked one goes to its next: `tap_combat()`). Six basic weapons (club, pitchfork, sickle, torch, sling, throwing stones) are rows in `BasicWeapons.STATS`: melee ones reuse `Sword.swing(direction, weapon)`, throwing ones `Player.throw_at()` with a pebble `Arrow` and a carried stone each, empty for a bow with no arrows (`docs/28_...`). `scenes/player/sword.tscn` is a child of Player: `Sword.swing(direction)` sweeps one image through an arc, and mid-swing calls `take_hit(damage, direction)` on anything in its Hitbox with that method. Any new Area2D on the player must also be excluded in `Farm._build_query`
- **Creatures**: `CreatureData` in `data/creatures/`; `Creature` (`scenes/creatures/creature.tscn`) is a CharacterBody2D with states WANDER and CHASE, floated in code, found in `World`. It's on collision layer 2, uses `motion_mode` Floating (the Grounded default made it ride the player like a platform), and finds the player through the `player` group. `_avoid_light()` keeps it `lantern_safe_radius` from anything in the `lantern_light` group (map and placed lanterns). `take_hit()` flashes, knocks back and defeats it; touching calls `Player.hurt()`, which has a 1 second safe time and does nothing while `Progress.day_changing`. `Farm`'s queries use mask 1, so creatures don't block tiles; the sword's Hitbox uses mask 3
- **Spawning**: `Farm/Spawner` (`CreatureSpawner`) clears creatures on `day_ended`, and on `day_started` and load adds `count_for_today()` of them (from `creature_first_day`, more as land heals, capped) on reachable clean cells beside the curse, away from light and the player. `creature_for()` picks hollows from column 52 east, and shades elsewhere. Random but seeded by the day. Tests that sit near the curse's edge past day 3 can be hit, so set `player._safe_left` high there
- **Curse shards**: creatures add their `drop` straight to `materials` when defeated. `Inventory.strong_holy_water` is crafted from 1 holy water + 2 shards (`RecipeNeed.holy_water`). Q/E with the Holy water tool toggles `Player.strong_water`, and `Healing.cleanse(center, strong)` heals a 5×5 patch
- **Health**: `Progress.hearts` (not saved, full each morning), `take_damage()`. At 0, `fainted` makes the HUD fade through `_fade_to_next_day()`, end the day, call `Player.return_home()` and show a message. `HeartsBar` draws them in code. `max_hearts` and `faint_money_percent` are in `data/balance.tres`
- **Purifying hoe**: crafted once (`Inventory.has_purifying_hoe`, saved). Phones use it through the Heal button. The Hoe tool on a cursed tile calls `Healing.purify()`, which heals that one tile for one of `hoe_uses_left` (from `hoe_daily_uses`, refilled every morning and on load)
- **Crafting**: `scenes/farm/workbench.tscn` at (976, 384): F calls `GameState.request_crafting()` → `scenes/ui/crafting_menu.tscn` (a scrolling list). Recipes are `RecipeData` (with `RecipeNeed`s: a crop or a material) in `data/recipes/`, listed in `Inventory.RECIPES`; `Inventory.craft()` checks, spends and gives the result
- **Menus**: `GameMenu` (`scripts/ui/game_menu.gd`) is the base for the shop, bag, crafting and pause menus: open, close, pause, `close_action`, and a `_refresh()` to override. They share `data/ui/menu_panel.tres`
- **Materials and bag**: `MaterialData` in `data/materials/`, listed in `Inventory.MATERIALS`, counts in `Inventory.materials` (saved). `scenes/ui/bag_menu.tscn` on key I shows crops, seeds, holy water and materials; it pauses the game like the shop, and won't open over another menu
- **Goal guide**: `GoalGuide` (`scripts/ui/goal_guide.gd`, a plain Node): one goal at a time from the `STEPS` table, then the long goal. Goals stay off the screen: a new one shows for 6 seconds on the HUD's `GoalLine` (`announced` signal), and `TasksMenu` lists now, the long goal and what's done, from the phone's small Tasks button or key G (`tasks`). Game code reports with `Progress.record_action("till")` into `guide_done` (saved; older saves get `GUIDE_FINISHED`, so they skip the lessons). `SaveGame.start_new_game()` sets `show_story`, which opens the story panel and pauses, so tests that start a new game must clear it or close the panel
- **HUD** (`scripts/ui/hud.gd`): hint line, day and money labels, StatusRows (top right: an icon and number each for holy water, strong water, shipping, the can and island healed, from `HUD.STATUS_ROWS`; tests read the words in `hud.status_text`), crop status and notice labels, tool/seed label (under the hearts; on phones both move up 24 pixels into the hidden hint line), fade rect. On computers `HUD/KeyToolBar` (`scripts/ui/key_tool_bar.gd`) shows the tool icons with their number keys at the bottom, highlights the selected one, and a click sends that key's action; it hides while touch controls are on. Tool icons come from `TouchControls.tool_icon()` (static). `_refresh()` runs on `inventory_changed`, so emit that when money changes. Notices take turns on one line (`_show_notice()`: 3 s alone, 1.5 s while others wait, max 4 waiting); tests read `hud.latest_notice()` and `hud._waiting_notices`, not the label, since a notice may be waiting
- **Pause menu**: `HUD/PauseMenu` (`scripts/ui/pause_menu.gd`): Esc (`ui_cancel`) opens it when nothing else is open and the day isn't changing; Resume, Settings (`HUD/SettingsMenu`, the title's `SettingsMenu`), Back to title (asks first, then `SaveGame.discard_unsaved()` reloads the morning's save). Phones get a pause button (iron bars icon) in the top right corner on the tool bar layer (the top right text moves left to make room) that sends `ui_cancel`; the big Action button shows what it will do, or a "!" for objects and under menus (menus say "Tap ! to close"), and an X shows only in Build mode
- **Touch**: `HUD/TouchControls` (`TouchControls`) shows only where `DisplayServer.is_touchscreen_available()`, or through `set_active(true)`. `ThumbStick` (`scripts/ui/thumb_stick.gd`, node `Joystick`: it starts where the thumb lands, the ring follows the thumb but stays inside a safe area, and it dims when idle; `_fit_joystick()` sizes its area to the lower left, up to the tool bar and from 40% down the screen, and it hides under menus; art comes from the theme's `VirtualJoystick` styles) drives the move actions, and `TouchScreenButton`s (built from tables) press normal actions, so game code doesn't know about touch. All help text naming a control goes through `GameState.controls(keyboard, touch)`, and menus set `keyboard_help` and `touch_help`; `tests/test_phone_ui.gd` checks for key names. Menus must not reach x = 501 on a 640-wide view (`TouchControls.menu_limit()`), which keeps Bag and Action showing, and a test checks this with a full bag. Tests fake fingers with `InputEventScreenTouch`, using `root.get_final_transform() * position`
- **Theme**: `data/ui/game_theme.tres` is set as `gui/theme/custom` in `project.godot`: m5x7 font at size 24 (keep to 16, 24 or 48), art panels and buttons through `StyleBoxTexture`, and the joystick. Change the look there, not per scene. Icons are `icon` fields on `CropData`, `MaterialData` and `RecipeData`, in `assets/items/`; `GameMenu._icon()` makes a fixed-size picture. On touch screens menus stay centered unless they would cover Act (`GameMenu._place()`, `TouchControls.act_left()`)
- **Sound**: `Audio` autoload (`scripts/autoload/audio.gd`). `Audio.play(&"name")` for effects (names listed in `Audio.EFFECTS`; a new one must be added there and to `docs/18_...`), `Audio.play_music(&"farm")`. Files are found by name in `assets/audio/effects/<name>.wav|.ogg` and `assets/audio/music/<name>.ogg|.mp3`, with extra versions `<name>_2`, `<name>_3`... played in turn (one version loops); missing ones are silent, `Audio.missing()` lists them. Buses Master, Music, Effects in `default_bus_layout.tres`. Every `BaseButton` gets the `click` sound automatically. Volume saved in `user://settings.cfg` (not the save; New Game keeps it). `SettingsMenu` (`scripts/ui/settings_menu.gd`, built in code, − and + buttons) sits on the title screen; reuse it in the pause menu. Tests check `Audio.last_requested`. With no window (headless, the tests) sounds are picked but not started, because quitting mid-sound leaks. The 21 effects are generated by `tools/make_sounds.gd` (one `sound_<name>()` recipe each; rerun it, then `--import`). Music from Suno: `farm.mp3` and `farm_2.mp3` (alternate), `title.mp3`. Every version plays in turn rather than Claude picking one (`docs/18_...`, "Choosing music"). If the user asks Claude to generate music, point to `docs/18_...` ("Can Claude generate the music too?"): effects yes, music not well, a placeholder drone only if they want one
- **Title**: `scenes/ui/title_screen.tscn` is the first scene (Continue, New Game, Settings, Quit, hidden on phones). New Game asks first if a save exists, with No focused, then calls `SaveGame.start_new_game()` (deletes the save, then `_reset()`). `SaveGame._reset()` calls each part's `reset()`, which must reset every saved value: it's also used by `discard_unsaved()`. To add a saved value: add it to `save_to()`, `load_from()` and `reset()` in `Inventory` or `Progress`; `tests/test_save_parts.gd` lists the file's keys, so add it there too
- **Main scene**: Main → Farm (Ground instance, Soil, Highlight), Mood, World (y-sorted: House at (912, 288), ShippingBox, ShopStall, 4 lantern posts, Player, crops), HUD (ShopMenu, BagMenu, CraftingMenu, PauseMenu, SettingsMenu, Fade)

## Art pipeline

- **Workflow**: the user generates art in ChatGPT/Codex; files land in the Codex folder for this machine (see "Two dev machines"). **Always look there first** when the user says art is ready: on Windows search `C:\Users\raksm\.codex\visualizations` recursively by time (`find ... -mmin -90`), since the date folder may not be the one you expect. Sometimes there's a `*-master.png` and a small version, sometimes only one file (2026-11-04). Copy the **master** (on the Mac, the only file) into `art_source/` and shrink with `tools/pixelize.gd`; never use ChatGPT's own small version (it loses detail)
- Find the real pixel size first (measure the color-run length of the master); keep it, don't squeeze art into a tile. Player sheets: `--scale 9.70 --frame-w 48 --frame-h 64`. Ground textures: `--height 128 --frame-w 128 --frame-h 128`. Objects: pick a height that fits next to the player and house rather than the master's pixel size (shipping box `--height 48 --frame-w 40 --frame-h 48`, stall `--height 96 --frame-w 96 --frame-h 96`, lantern `--height 72 --frame-w 48 --frame-h 72`, shrine `--height 80 --frame-w 64 --frame-h 80`, tree `--height 96 --frame-w 96 --frame-h 96`, rock `--height 36 --frame-w 48 --frame-h 40`). Remains use the same `--scale` as the whole object (tree 12.34, rock 23.11). Add `--single true` for art in separate pieces (a pause icon's two bars too), `--crop-x`, `--crop-w` to cut one section from wider art, `--crop-y`, `--crop-h` to cut up and down, `--circle true` to keep only the circle filling the cut, and `--outline true` to keep thin dark lines when art shrinks a lot (wardthorn stages), and `--middle true` to centre icons up and down (a short one would sit low). Check for faint see-through halos (alpha between 0 and 0.5) when measuring bounds
- Check walk cycles: frames 1 and 3 must lift opposite legs (walk_down needed a fix: frame 3's legs replaced with frame 1's legs mirrored)

## Testing

- **Run `tests/run_all.sh` before every commit** (a few seconds; it uses a temporary home folder, so it never touches the real save, and it fails on any error or warning). Add a test with each new feature: `tests/test_<feature>.gd`, or a `<name>_1_play.gd` and `<name>_2_check.gd` pair for anything that must survive a restart (add pairs to the script). Works on both Mac and Windows
- Headless checks: `--headless --path . --script <test.gd>` with a `SceneTree` script that instantiates `res://scenes/main/main.tscn` and simulates input (`Input.action_press`, or `Input.parse_input_event(InputEventAction)` for `_unhandled_input`). Use `--fixed-fps 60` when timing matters (fades)
- Farm is readied before World, so `player.reach` and other `@onready` values on World's nodes are null in `Farm._ready()`; use `get_node()` there, and guard with `is_node_ready()` in anything Farm calls during setup
- `GameState.BALANCE.x` is fixed when a script compiles, because `BALANCE` is a `const`. To change a number in a test, use `load("res://data/balance.tres").x = ...` before loading the main scene
- Test scripts can't reference autoloads by name (compiled first); use `root.get_node("Inventory")` and so on (tests call them `inv`, `progress`, `saves`, `gs`). This also rules out `class_name`s whose scripts use autoloads (`n is CleanseEffect` fails to compile); check `scene_file_path` instead. A failed test script never quits, so run tests with a time limit
- Screenshots: run without `--headless`, save `root.get_texture().get_image()` after ~30 frames, then look at the PNG
- Run `--headless --import` after adding new images or scripts
- Creatures wander randomly, so a test about them can be flaky: run it several times before trusting it. Tile collision updates on the next physics frame, so wait 2 frames after healing before checking `is_farmable()`
- Tests that call `end_day()` write the save, so run a single test with a temporary home folder too: `HOME=<temp dir>` on Mac, `APPDATA=<temp dir>` on Windows

## Known issues and quirks

- `input_devices/pointing/emulate_touch_from_mouse` shows the phone controls on a computer for testing. Turn it off before running tests or committing: with it on, 11 tests fail and a Steam build would show touch controls
- `project.godot`: Godot itself moves the `2d/snap/snap_2d_transforms_to_pixel` line when it runs; harmless, `git restore project.godot` before committing, **but only after checking `git diff project.godot` shows nothing else**: a real change there (like a new autoload) would be lost
- Quitting the real game while a sound plays prints "ObjectDB instances were leaked" in the console: a harmless Godot cleanup quirk (`docs/16_...`)
- Fences: `Fence.fit()` picks side-on or vertical art from its neighbors (`Builder.fit_neighbors()`, after place, pick up and restore; any building with a `fit()` method gets the same call). Row ends and corners still show a bit of rail sticking out (no end or corner pieces yet)
- Moths, wind and grass movement: planned in `docs/29_...` (animation plan)
- Standing "facing right" pose is separate art, slightly different from the mirrored walk side

## Display and input

- Base resolution 640×360 (20×11 tiles of 32px), window 1280×720, stretch mode `canvas_items` (not `viewport`: that made movement jump in 2-pixel steps), integer scaling
- `ScreenFit` autoload (`scripts/autoload/screen_fit.gd`) sizes the view to the screen at a whole-number scale, so the view can be bigger than 640×360 (924×426 on the user's phone). New HUD items must use anchors or follow an edge (`TouchControls._follow_edge()`), never assume 640×360. Headless windows are 64×64, so tests stay at 640×360 unless they set `root.size`
- Texture filter Nearest, 2D transforms snap to pixel
- Physics interpolation ON (smooth movement on 120 Hz+ monitors with 60 Hz physics); cameras use the physics process callback
- Input actions (in `project.godot`): `move_up/down/left/right`, `tool_1`–`tool_7`, `seed_prev`, `seed_next`, `use_tool`, `interact`, `action`, `inventory`, `switch_mode` (C), `build_tool` (V), `book` (B), `tasks` (G)

## Tools

- `tools/` (ignored by Godot): `build_bow_frames.gd` lines up the bow's 3 shooting frames. `build_farm_map.gd` builds the tileset and ground scene. `build_curse_edges.gd` builds the curse edge pieces. `split_row.gd` cuts a sheet into one file per frame. `make_sounds.gd` makes the sound effects from waves. `build_ward_packet.gd` draws the wardthorn pod on the other seed packets' paper. `build_book_page.gd` makes the book's page from its AI art, with solid insides. `build_hoe_icon.gd` makes the purifying hoe's icon from the head of its art. `build_ward_ripe.gd` cuts the ripe wardthorn's frames on a fixed grid. `balance_check.gd` estimates the pace (days to the first shrine) from the real map and data; rerun it after changing numbers. `pixelize.gd` shrinks AI art to real pixel size: `--headless --path . --script tools/pixelize.gd -- --in art_source/... --out assets/... --height 64 --frame-w 48 --frame-h 64`
